# jevailab 积分账户与明细设计

**日期：** 2026-10-21  
**状态：** 已确认，待实施  
**范围：** Waffo 付款到账、图片创作积分扣除与返还、登录用户积分明细、年度订阅的按月积分发放。

## 1. 已确认的业务规则

| 产品 | 首次到账 | 后续到账 | 积分有效期 / 结转 |
| --- | ---: | --- | --- |
| 入门包 | 66 积分 | 无 | 自购买日起 12 个月有效 |
| 专业月付 | 180 积分 | 每次月度付款成功后发放 180 积分 | 本账单周期结束即失效，不结转 |
| 专业年付 | 240 积分 | 在已支付年度内每月发放 240 积分，共 12 期 | 每月刷新，不结转；不一次性发放 2,880 积分 |

生成任务提交时只冻结积分；KIE 异步任务成功后才确认消耗。任务失败、被拒绝、超时或未产出时释放对应冻结积分。部分成功时仅消耗实际成功部分，剩余积分返还。

退款采用 Waffo 已验签的 `refund.succeeded` 事件作为唯一生效依据。部分退款按关联积分批次的未使用余额回收；成功退款后，年付后续尚未发放的月份必须取消。若待回收积分已经被使用，账户进入受限状态并保留人工处理记录，不自动制造负数积分。

## 2. 核心原则

- 浏览器、支付完成跳转页和客户端金额都不能增加积分；只有已验签、去重后的 Waffo Webhook 可以入账。
- 每一笔余额变化都写不可变流水；流水只追加，不能用更新历史记录替代。
- 积分以“批次（lot）”管理。订阅积分的失效或退款只能影响自己的批次，不能误扣入门包或其他购买批次。
- KIE API 密钥只保留在服务端。KIE 创建任务不表示成功，必须以服务端轮询或已验签回调完成结算。
- 所有面向用户的名称、状态和错误文案都提供中文、英文两种翻译。

## 3. 数据模型

保留现有 `image_wallets` 作为快速余额投影，保留 `image_credit_ledger` 作为展示给用户的不可变账本；新增批次和计划表，避免把会失效的订阅积分与长期有效积分混成一个余额。

### `image_credit_lots`

- `id`、`user_id`、`source_type`（`purchase` / `subscription` / `manual`）、`source_payment_id`、`source_event_key`；
- `issued_credits`、`available_credits`、`reserved_credits`；
- `available_at`、`expires_at`、`status`（`active` / `expired` / `revoked` / `restricted`）；
- `plan_key`（`starter` / `monthly` / `annual`）及创建、更新时间。

消费按最早到期优先分配；无到期时间的入门包排在订阅批次之后，避免先消耗长期积分。

### `image_credit_reservations`

一条生成任务可占用多个积分批次。记录 `job_id`、`lot_id`、`reserved_credits`、`captured_credits`、`released_credits`、结算状态。它使失败返还和部分成功结算可重复执行而不重复扣费。

### `image_credit_schedules`

用于年付。首次付款成功时创建 12 个每月 240 积分的发放计划：当月计划立即执行，其余计划在每月账单日到期。字段包括 `subscription_id`、`user_id`、`scheduled_at`、`credits`、`event_key`、`state`（`scheduled` / `granted` / `canceled`）。

Cloudflare Cron 每小时处理到期计划、失效的订阅批次和卡住的生成任务。每项操作通过唯一 `event_key` 保证重试安全。

### 账本事件

| 事件 | 可用余额变化 | 冻结余额变化 | 用户明细显示 |
| --- | ---: | ---: | --- |
| `PURCHASE_GRANT` | + | 0 | 购买到账 |
| `SUBSCRIPTION_GRANT` | + | 0 | 月度积分到账 |
| `RESERVE` | - | + | 创作处理中 |
| `CAPTURE` | 0 | - | 图片生成消耗 |
| `RELEASE` | + | - | 生成失败返还 |
| `EXPIRE` | - | 0 | 周期积分失效 |
| `REFUND_REVOCATION` | - | 0 | 退款后回收 |
| `REFUND_RESTRICTED` | 0 | 0 | 退款待人工处理 |

## 4. Waffo 到账与退款流程

1. Waffo 订单的 `userId`、`priceId` 和订单级 `paymentReference` 随服务器创建的结账会话传递。
2. Webhook 验签、确认环境匹配后，以 `eventId` 作为幂等键写入支付记录及积分流水。
3. 一次性订单完成时，按 `priceId` 映射发放 66 积分；订阅激活时发放首期积分。
4. 月付以 `subscription.payment_succeeded` 的支付 ID 作为账单期幂等键，每成功付款一次发放 180 积分。
5. 年付只在首次付款创建 12 个月的发放计划；Cron 根据计划逐月发放 240 积分。年度续费时生成新一年的计划，不能重复旧计划。
6. `refund.succeeded` 读取退款金额、订单标识和退款工单标识。全额或部分退款均先写退款流水，再回收该支付来源仍可用的积分；退款金额不足以覆盖整笔购买时，按退款比例回收。年付同时取消未来计划。
7. Waffo 退款工单创建或 `refund.failed` 只记操作状态，不减少积分；只有 `refund.succeeded` 生效。

## 5. 图片生成结算流程

1. 报价服务端持久化 `image_quotes`，开始生成时对可用积分执行原子预留，创建 `image_generation_jobs` 和多条批次预留记录。
2. 调用 KIE 创建任务失败时，立即释放全部预留；浏览器获得可理解的错误，但不拿到供应商敏感细节。
3. KIE 回调/轮询确认成功、部分成功或失败后，服务端只结算一次：成功部分捕获，未成功部分释放。
4. 结算同步追加 `image_credit_ledger`，并更新 `image_wallets` 投影；用户刷新积分页即可看到最新结果。

## 6. 登录后的积分明细页

新增受保护路由 `/settings/credits`，置于设置菜单的“账单”旁边：

- 顶部显示可用积分、生成中冻结积分、下次订阅积分到账时间；
- “购买积分”跳转至既有首发套餐页；
- 账本表格显示时间、类型、说明、变动积分、状态、余额与可选订单/任务编号；
- 支持“全部 / 购买 / 消耗 / 返还 / 失效 / 退款调整”筛选及安全分页；
- 仅能读取当前登录用户，订单与任务编号不泄露其他用户资料；
- 路由、侧边栏、标题、筛选项、空状态和错误信息均接入中英文翻译。

## 7. 非目标与验收

本次不做用户自助退款页面或后台人工退款审批 UI；先让 Waffo 后台/既有入口完成退款，Webhook 正确同步积分。

验收必须覆盖：重复 Webhook 不重复到账、年付每月只发 240、月付/年付积分不结转、入门包不被订阅积分失效影响、失败任务全额返还、部分任务正确返还、部分退款不按全额扣回、未登录用户不能读取积分明细、价格页年付文案不再宣称全年积分一次到账。
