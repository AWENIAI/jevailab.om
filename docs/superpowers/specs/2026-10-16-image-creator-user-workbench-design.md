# AI 图片创作用户工作台改版设计

**日期：** 2026-10-16  
**状态：** 实施中  
**范围：** 首页 Hero 下方的「开始创作」用户端模块，以及支撑该模块的私有服务端接口与数据结构。

## 1. 目标与边界

将当前简化版生图卡片替换为一个可真实运行的创作工作台。页面继续使用网站现有的深色背景、橙色主操作、圆角卡片、细边框和文字层级；不照搬参考图的米白/酒红配色。

本次只做用户端，不做：

- 模板管理后台、模板编辑或发布能力；
- 充值/支付页、公开作品广场；
- 真实 NSFW 供应商接入。

模板仅由服务端预置。`basePrompt`、`negativePrompt` 和供应商原始请求不得进入浏览器、公开接口、页面源码或日志。

## 2. 页面结构

### 桌面端（宽度 >= 1280px）

工作台使用三栏布局，置于 Hero CTA 下方：

1. **模板栏（左）**
   - 搜索、分类（全部 / 摄影 / 插画 / 海报 / 艺术）和 3:4 裁切的模板卡片；
   - 卡片展示封面、名称、简短描述和选中状态；
   - 固定「自由创作」入口，取消模板选择。
2. **创作栏（中）**
   - 当前模板摘要；
   - 一张参考图上传区；
   - 补充描述；
   - 清晰度（1K SD / 2K HD）、比例、生成张数；
   - 服务端报价、余额变化、隐私与内容安全同意项；
   - 生成按钮及排队/生成/审核状态。
3. **预览与历史栏（右）**
   - 最新任务的状态、已审核通过的输出图；
   - 下载、再次生成；
   - 当前用户私有历史列表与删除操作。

中小屏按顺序降级：模板 + 创作两栏；手机端单栏。所有功能保持可用，不能仅隐藏在桌面布局中。

### 交互约束

- 模板封面始终以 `3 / 4` 显示，但不改变生成比例；
- 只能上传一张 JPG、PNG 或 WebP 参考图，最大 10 MiB；
- 自由创作必须填写描述；模板是否要求/禁止参考图由服务端模板 `inputPolicy` 决定；
- 模式为 `1K SD` 和 `2K HD`；比例支持 Auto、9:16、2:3、3:4、1:1、4:3、3:2、16:9、21:9；数量 1–9；
- 参数变化后 300 ms 防抖请求服务端报价；浏览器只显示报价，不自行计算或扣积分；
- 未勾选隐私与内容安全同意项、报价失效、余额不足、上传未完成或审核未通过时，生成按钮禁用；
- 参考图、用户描述、生成输出均显示相应审核状态；不显示审核供应商实现细节。

## 3. 前端状态与组件边界

将现有 `AiImageCreatorSection` 拆成可测试的用户端组件：

- `ImageCreatorWorkbench`：加载模板、能力、政策与当前用户钱包；
- `TemplateBrowser`：仅使用公开模板 DTO；
- `CreatorForm`：草稿状态、上传、报价与提交；
- `GenerationPreview`：当前任务状态、输出图、下载和再次生成；
- `GenerationHistory`：当前登录用户的私有历史；
- `CreditQuote`、`SafetyConsent`、`ReferenceUpload`：独立且可复用。

页面不持有积分真值，也不保存供应商请求、私有存储路径或模板私有提示词。浏览器只保存短期草稿、公开模板字段、报价 ID 和任务 ID。

## 4. 服务端接口

接口按需求文档的用户端合同实现，并适配项目现有 TanStack Start server function / Cloudflare Workers 架构：

- `templates`：公开可搜索模板 DTO；
- `capabilities`：启用的模式、比例、数量上限及服务可用性；
- `policies`：隐私与安全政策版本、链接；
- `wallet` / `wallet.transactions`：登录用户积分与账本；
- `assets/upload-intent`、`assets/{id}/complete`、删除：私有参考图上传与审核；
- `quotes`：服务端权威报价，含过期时间、价格版本、解析后的比例；
- `generations`：以幂等键创建任务、查询私有历史；
- `generations/{id}`：任务进度、已审核输出和删除；
- `outputs/{id}/download`：所有权校验后返回短期私有下载地址或代理下载。

所有写入接口均需登录。每次读取任务、图片、下载地址或删除时，都必须通过 `userId` 所有权过滤。

## 5. 审核接口（本期预留，不接供应商）

定义仅服务端可用的审核适配器，覆盖三段审核：

```ts
type ModerationSubject =
  | { kind: 'prompt'; text: string }
  | { kind: 'reference_image'; assetId: string; storageKey: string }
  | { kind: 'generated_image'; jobId: string; outputId: string; storageKey: string };

type ModerationResult = {
  decision: 'approved' | 'rejected' | 'manual_review' | 'unavailable';
  policyVersion: string;
  reasonCode?: string;
};

interface ModerationProvider {
  review(subject: ModerationSubject): Promise<ModerationResult>;
}
```

规则：

- 审核供应商、密钥、原始结果与敏感原因仅保留在服务端；
- 生产环境未配置审核适配器时，任务创建必须失败并给出「内容审核尚未配置，暂不能生成」的安全提示（fail closed）；
- 开发环境可显式配置本地 mock 审核器，且仅能通过 `WAFFO_DEBUG` 之外的独立开发开关启用，不能意外部署到生产；
- 参考图在写入可用区前审核；生成结果先写入隔离区，审核通过后再复制到用户私有输出区；未通过结果不提供下载；
- 前端不能调用审核供应商，也不能拿到私有 R2 key。

## 6. 图像供应商与任务状态

现有 Kie 调用改为服务端 `ImageGenerationProvider` 适配器，不再让浏览器保存可直接查询供应商的签名 ticket。

**当前适配器边界：** 已接入的 Kie 调用仅支持文本生图。因此参考图会保留其私有上传与审核接口，但在图生图适配器实际接入前，任务创建会明确提示用户移除参考图；不得静默忽略参考图并把结果标记为图生图。

任务状态：

`queued -> running -> moderating -> completed | partial | failed | rejected | reconciling`

处理流程：

1. 校验草稿、模板规则、参考图状态、同意项与未过期报价；
2. 在一个 D1 事务中写任务、写积分预留账本、更新钱包可用/冻结积分；
3. 将任务送入现有 Worker 可执行的后台处理通道；如暂未配置队列，使用受控轮询/补偿任务，不允许浏览器直接接管；
4. 服务端结合模板私有提示词、用户描述和参考图调用 Kie；
5. 将供应商原始输出放入隔离区并逐张审核；
6. 审核通过的输出转入私有 R2，更新任务，按真实成功张数结算或释放冻结积分；
7. 前端以轮询为默认方式显示进度；后续可增加授权 SSE。

## 7. D1 与 R2 数据模型

不直接套用文档中的 PostgreSQL SQL，而是在现有 Drizzle SQLite/D1 schema 中新增对应表：

- `image_templates`：服务端预置模板（含私有提示词列）；
- `image_assets`：用户参考图元数据与审核状态；
- `image_wallets`、`image_credit_ledger`：可用/冻结积分与不可变账本；
- `image_quotes`：报价快照、价格版本、过期时间；
- `image_generation_jobs`：请求快照、幂等键、状态、供应商任务 ID、结算信息；
- `image_generation_outputs`：每张输出的隔离/私有状态与审核版本；
- `image_job_outbox`：可靠投递/补偿任务记录。

时间采用项目既有的毫秒整数格式，ID 使用服务端生成的文本 ID。迁移只新增表和索引，绝不修改 Better Auth 表或现有支付记录。

R2 路径分为：

- `image-assets/{userId}/...`：参考图私有文件；
- `image-quarantine/{jobId}/...`：未审核生成结果，不对用户开放；
- `image-outputs/{userId}/{jobId}/...`：审核通过的私有成品。

## 8. 积分与报价

积分价格由服务端版本化配置提供，不在前端常量中硬编码。初始开发配置可用文档示例（1K 每张 2、2K 每张 5），上线前由产品配置替换。

创建任务时按 `quoteId` 与当前钱包原子预留积分；任务只会以一次结算/释放账本收尾。重复提交使用 `userId + Idempotency-Key` 返回原任务，不重复扣积分。

## 9. 安全与隐私

- 不读取、记录或返回环境变量、私钥、审核密钥；
- 所有上传文件在服务端再次验证 MIME、大小、所有者和可用状态；
- 所有模板公开 DTO 均由白名单映射生成；
- 历史、原图和下载只能由本人访问；下载 URL 短期有效；
- 删除历史先隐藏数据库记录，再进入异步 R2 清理；
- 错误响应使用稳定错误码和 request ID，不能将供应商报错、密钥或私有 prompt 直接呈现。

## 10. 实施与验收顺序

1. 建立纯类型、模板公开映射、参数校验、比例/价格计算及单元测试；
2. 新增 D1 schema 和迁移，写钱包/报价/任务仓储；
3. 完成审核与图像供应商适配器接口，采用生产 fail-closed 实现；
4. 完成上传、报价、任务、历史、下载的 server functions；
5. 重构首页工作台三栏 UI 与响应式状态；
6. 对接 Kie 后台处理、私有 R2 输出和任务轮询；
7. 通过单元、类型检查、构建和登录用户端手工验收。

验收重点：模板私有提示词不泄露；未配置审核时生产生成被阻断；同一幂等键不重复扣分；失败/部分成功正确释放积分；他人无法读、下载或删除任务与图片；所有模板卡为 3:4 显示；页面风格与现有官网一致。
