# Jevailab 小程序 · 后端接口契约（REST 层 + 图生图改造）

> 配套：`小程序开发规划与架构设计.md`、`../miniprogram/`（前端工程）。
> 本文定义小程序调用的后端 REST 接口，以及把现有 image-creator 工作流接入「图生图」所需的后端改动。
> 设计原则：**业务逻辑零重复**——REST 层包裹现有 `src/api/image-creator.ts`、`src/db/image-creator.schema.ts`、`src/lib/image-creator/*`，仅新增「小程序适配层」。

---

## 1. 接入方式

- 在现有 Cloudflare Worker 新增一组标准 HTTPS JSON 接口，前缀 `/api/miniprogram/*`。
- 小程序用 `wx.request` 调用（见 `miniprogram/utils/request.js`），**不用**现有 TanStack serverFn 的 RPC。
- **认证**：现有 Better Auth 是 cookie session（Web 端）。小程序改用 **Bearer Token**——登录后把 token 存 `wx.setStorageSync('access_token')`，请求统一注入 `Authorization` 头；401 触发重新登录（见 `utils/request.js`）。
- **域名与备案**：`api.jevailab.com` 需 ICP 备案（主体须与小程序一致），并在微信后台配置为 request / uploadFile / downloadFile 合法域名。`*.workers.dev` 不可用。**个人主体若启用虚拟支付，还须完成「小程序备案」**（MP 后台）。

## 2. 接口契约（与小程序调用一一对应）

### 2.1 微信登录
`POST /api/miniprogram/auth/login`
- 请求：`{ "code": "<wx.login 返回的 code>" }`
- 处理：Worker 调微信 `code2session` 拿 openid → 关联/创建 Better Auth 用户（可借开放平台 unionid 与 Web 账号打通）→ 签发小程序 Bearer Token。
- 响应：`{ "accessToken": "...", "user": { "id", "email?", "name?" } }`

### 2.2 模板
`GET /api/miniprogram/templates`
- 响应：`{ "items": [ TemplateDTO ], "categories": string[] }`
- `TemplateDTO`：`{ id, name, category, description, coverUrl, exampleUrl, inputPolicy: "required"|"optional"|"forbidden", defaultMode, defaultRatio, defaultCount }`（白名单映射，绝不下发 `basePrompt`/`negativePrompt`）。

### 2.3 能力
`GET /api/miniprogram/capabilities`
- 响应：`{ "modes": ["1K_SD","2K_HD"], "ratios": [...], "maxCount": 9, "referenceImage": { "maxBytes": 10485760, "mediaTypes": ["image/jpeg","image/png","image/webp"] } }`

### 2.4 政策
`GET /api/miniprogram/policy`
- 响应：`{ "version": "2026-10-16", "privacyUrl": "/privacy", "termsUrl": "/terms" }`

### 2.5 报价（服务端权威，防抖 300ms）
`POST /api/miniprogram/quote`
- 请求：`{ templateId, referenceAssetId, mode, ratio, count, extraPrompt }`
- 响应：`{ priceVersion, unitCredits, totalCredits, quoteId, resolvedRatio, expiresAt, walletAvailable?, walletEstimatedAfter? }`

### 2.6 参考图上传（图生图前置，经审核）
`POST /api/miniprogram/upload`（multipart `file`）
- 处理：写入 R2 前调审核适配器；通过才落库 `image_assets`。
- 响应：`{ "assetId": "...", "fileName": "...", "previewUrl": "..." }`

### 2.7 参考图删除
`POST /api/miniprogram/upload/delete`
- 请求：`{ "assetId": "..." }` → 响应：`{ "deleted": true }`

### 2.8 创建生成任务
`POST /api/miniprogram/generations`
- 请求：`{ templateId, referenceAssetId, mode, ratio, count, extraPrompt, consentAccepted: true, policyVersion, idempotencyKey? }`
- 处理：校验 → 钱包预留积分（幂等键防重复扣费）→ 送入后台处理（图生图时把 `referenceImageUrl` 传给供应商）。
- 响应：`{ "id": "...", "status": "queued", ... }`

### 2.9 历史列表
`GET /api/miniprogram/generations`
- 响应：`{ "items": [ JobSummary ] }`，`JobSummary`：`{ id, templateName?, mode, ratio, count, status, createdAt, outputs: [{id,url}] }`

### 2.10 任务详情（轮询）
`GET /api/miniprogram/generations/:id`
- 响应：`{ id, status, outputs: [{id, url, state}], templateName?, mode, ratio, count, createdAt }`
- 前端每 3s 轮询，直到 `completed|partial|failed|rejected`。

### 2.11 删除任务
`DELETE /api/miniprogram/generations/:id` → `{ "deleted": true }`

### 2.12 输出下载
`GET /api/miniprogram/outputs/:id/download`
- 响应：`{ "url": "<短期私有地址>" }`（所有权校验后返回，过期后重取）。

### 2.13 钱包
`GET /api/miniprogram/wallet` → `{ "availableCredits": N, "reservedCredits": N }`

### 2.14 创作额度包下单（个人虚拟支付）
`POST /api/miniprogram/pay/order`
- 请求：`{ "productId": "quota_200" }`（productId 对应微信后台【道具管理】创建的道具 ID）。
- 处理：在现有 `payment` 抽象中新增**虚拟支付适配层 `virtualpay.ts`**——后端用 OfferID + 现网 AppKey 生成 `signData`（JSON：offerId / buyQuantity / env=0 / currencyType=CNY / productId / goodsPrice(分) / outTradeNo / attach）与两套签名 `paySig`（HMAC-SHA256，密钥 AppKey）、`signature`（HMAC-SHA256，密钥 sessionKey）；`outTradeNo` 每次唯一（8–32 位，不以 `_` 开头）。
- 响应：`{ "payData": { "signData", "mode":"short_series_goods", "paySig", "signature" } }`（透传给前端 `wx.requestVirtualPayment`）。

### 2.15 发货推送（平台 → 服务端）
`POST /api/miniprogram/pay/notify`
- 描述：支付成功后平台向配置的「消息推送」URL 推送 XML（`Event=xpay_goods_deliver_notify`）。
- 处理：解析 `WeChatPayInfo.MchOrderNo`（平台单号 `wx_order_id`）→ **幂等**去重（同 `wx_order_id` 只发一次货）→ 据 `OpenId`+`ProductId`+`Quantity` 给对应用户增加生图额度（内部 credits 账本）→ 返回 `<xml><ErrCode>0</ErrCode></xml>`（失败平台重试，最多 15 次）。

### 2.16 兜底查单
`POST /api/miniprogram/pay/query`
- 请求：`{ "outTradeNo": "..." }` → 后端转发 `query_order`（带 pay_sig 签名）→ 返回订单支付状态；用于推送丢失时定时补发货。

## 3. 图生图后端改造（关键执行项）

现有地基已就位，仅需两处改动即可开启图生图：

### 3.1 供应商切换为 GPT Image 2.5 Sunburst
- `ImageGenerationProviderRequest` **已实现** `referenceImageUrl?` 字段（`src/lib/image-creator/provider.server.ts`）。
- `validateImageCreatorDraft` **已支持** `referenceAssetId` 与模板 `inputPolicy`（`src/lib/image-creator/validation.ts`）。
- 新增一个支持 image-to-image 的 provider（走 fal.ai 或 OpenAI images edit，参考现有 `editAiImage` / `fal-ai/nano-banana/edit` 的 `image_urls` 传参方式），在 `startImageCreatorGeneration` 中替代 Kie 调用，把 `referenceAssetId` 解析出的私有 R2 地址作为 `referenceImageUrl` 传入。

### 3.2 移除参考图硬拒绝
`src/api/image-creator.ts` 中 `startImageCreatorGeneration` 约 206–212 行当前逻辑：
```ts
if (draft.referenceAssetId) {
  throw new Error('当前图生图服务尚未接入。请移除参考图后使用文本生图…');
}
```
改为：当供应商支持图生图时允许带 `referenceAssetId`；当模板 `inputPolicy === 'forbidden'` 时仍拒绝（由 `validateImageCreatorDraft` 已在前面拦截）。

### 3.3 任务编排保持不变
状态机 `queued → running → moderating → completed | partial | failed | rejected | reconciling`、隔离区审核、`image-outputs/{userId}/{jobId}` 私有区逻辑全部复用，无需重写。

## 4. 个人虚拟支付接入要点
> 2026-08-31 起微信向个人主体小程序开放虚拟支付（工具类目 + 认证 + 备案）。**与企业版微信支付（商户号 V3 + `wx.requestPayment`）完全两套体系，不要复用。**

- 后端不接商户号，改为在 `src/payment/provider/` 新增 `virtualpay.ts`：用 **OfferID + 现网 AppKey** 做 HMAC-SHA256 签名；需处理两类签名 `paySig`（AppKey）与 `signature`（sessionKey，来自 `auth.code2Session`）。
- **只做道具直购**：售卖标的为「创作额度包」（`quota_60/200/600`），**禁止**以"积分/虚拟货币"作为购买标的（平台红线；内部仍用 `image_wallets` 的 credits 计量）。
- 发货以平台「发货推送」(`/pay/notify`) 为主、`query_order` 查单兜底；前端 `success` 回调不作为发货依据。
- 金额单位用「分」，全程不换算；`env` 固定 `0`；`outTradeNo` 每次重新生成且唯一。
- 费率/限额：月限额 10 万，Android 1% / iOS 12%（Apple 佣金）；iOS 需微信 ≥ 8.0.68（前端已做版本校验）。
- 道具在微信后台【道具管理】创建并发布；价格须与 `goodsPrice` 一致。

## 5. 验收清单（后端）
- [ ] `/api/miniprogram/*` 全部接口返回结构与前端点位一致（用 Postman/本地 Worker 验证）。
- [ ] 微信登录可拿到 token；Bearer Token 在所有写入接口通过 `userId` 所有权过滤。
- [ ] 图生图：带 `referenceAssetId` 的任务能正确传入供应商并产出审核通过的结果。
- [ ] 未配置审核时生产环境生成被阻断（fail-closed）。
- [ ] 同一幂等键不重复扣积分；失败/部分成功正确释放积分。
- [ ] 个人虚拟支付：`/pay/order` 返回合法 payData；`wx.requestVirtualPayment` 拉起成功；`/pay/notify` 验签 + 幂等发货（wx_order_id 去重）；`/pay/query` 兜底查单可补发货；道具价格与后台一致。
