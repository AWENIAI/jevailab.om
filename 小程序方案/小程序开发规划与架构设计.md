# Jevailab 图片编辑器 → 微信小程序：开发规划与架构设计

> 文档定位：把现有 Web 端「AI 图片创作工作台」移植为微信小程序的第一阶段交付物。
> 本文覆盖三件事：**开发规划（路线图）**、**需要准备的工具与账号清单**、**小程序架构设计**。
> 后续阶段（脚手架代码、接口契约、提审）在此基础上展开。

## 1. 现有功能盘点（移植范围）

我通读了 `src/api/image-creator.ts`、`src/db/image-creator.schema.ts`、`src/lib/image-creator/*`、`docs/ai.md` 与工作台设计稿，确认「图片编辑器」= **AI 图片创作工作台**，能力如下：

### 1.1 用户端三栏工作台（参考 `docs/superpowers/specs/2026-10-16-image-creator-user-workbench-design.md`）
- **模板栏**：搜索、分类（摄影/插画/海报/艺术）、3:4 封面卡片、固定「自由创作」入口。
- **创作栏**：模板摘要、参考图上传（≤10 MiB，JPG/PNG/WebP）、补充描述、清晰度（1K SD / 2K HD）、比例（9 种）、生成张数（1–9）、服务端报价、余额、隐私/内容安全同意项、生成按钮（带排队/生成/审核状态）。
- **预览与历史栏**：任务状态、已审核输出图、下载、再次生成、私有历史列表与删除。

### 1.2 后端已具备的能力（直接复用，不必重造）
- **模板种子** `imageTemplateSeeds` + 公开 DTO 白名单映射（`toPublicImageTemplate`）。
- **报价引擎** `getImageCreatorQuote`：1K=2 积分 / 2K=5 积分，价格版本化（`IMAGE_CREATOR_PRICE_VERSION`）。
- **钱包与账本** `imageWallets` + `imageCreditLedger`：可用/冻结积分、不可变账本、幂等键防重复扣费。
- **存储** Cloudflare R2：`image-assets/{userId}`、`image-quarantine/{jobId}`（隔离区）、`image-outputs/{userId}/{jobId}`（私有成品）。
- **审核适配器** fail-closed：未配置审核则生成被阻断；参考图先审后存、生成结果先入隔离区再转私有区。
- **任务编排** `imageGenerationJobs` + `imageGenerationOutputs` + `image_job_outbox`（补偿/轮询）。
- **图像供应商** Kie（当前仅文本生图）。

### 1.3 明确不在本期小程序范围内
- 模板管理后台/编辑/发布（服务端预置即可）。
- 公开作品广场、真实 NSFW 供应商接入（额度购买走小程序内「个人虚拟支付」道具直购，不另做网页充值页）。

> **图生图已纳入首版（2026-10-19 更新）**：GPT Image 2.5 Sunburst 支持图生图。现有代码已具备图生图地基——`ImageGenerationProviderRequest.referenceImageUrl`（provider 层已预留）、`validateImageCreatorDraft` 的 `referenceAssetId` 与模板 `inputPolicy`（required/forbidden/optional）。执行时只需：
> 1. 将 image-creator 的生成供应商从 Kie（纯文本）切换为 GPT Image 2.5 Sunburst（支持 image-to-image，走 fal.ai 或 OpenAI images edit，参考现有 `editAiImage` / `fal-ai/nano-banana/edit` 的 `image_urls` 传参方式）；
> 2. 移除 `src/api/image-creator.ts` 中 `startImageCreatorGeneration` 对 `referenceAssetId` 的硬拒绝分支（约 206–212 行）；
> 3. 小程序端参考图上传→审核→随请求传入 `referenceAssetId` 的流程本就就绪，供应商切换后即生效。

## 2. 开发规划（分阶段路线图）

> 工期为单人/小团队估算，含联调与提审缓冲。Phase 0 可与 Phase 1 并行启动。

### Phase 0 — 资质与基础设施准备（≈1–2 周，阻塞项）
- 注册**个人主体**微信小程序（持有居民身份证），服务类目选 **「工具 - 图片/音视频处理」**（个人虚拟支付硬性要求类目须含「工具」）。
- 完成**小程序备案 + 域名 ICP 备案**（个人虚拟支付开通条件明确要求"已完成认证、备案"；域名用于小程序 request/upload/download 合法域名，必须备案且主体与小程序一致）。
- 开通**个人虚拟支付**：MP 后台【支付与交易 → 虚拟支付】开通，获取 **AppID / OfferID / 现网 AppKey**；在【道具管理】创建"创作额度包"道具（10/50/200 次等）并发布。
- 起草**隐私协议**文本、准备工具类目所需的合规说明（见 §3、§5）。
- 产出：已备案域名 + 个人小程序 AppID + 虚拟支付 OfferID/AppKey + 已发布道具。

### Phase 1 — 后端小程序 API 层 + 微信登录最小闭环（≈1–1.5 周）
- 在现有 Worker 新增 `/api/miniprogram/*` REST 层（标准 JSON，供 `wx.request` 调用），包裹现有 `image-creator` 逻辑。
- 实现微信登录桥接：`wx.login()` code → Worker 调微信 `code2session` → openid → 关联/创建 Better Auth 用户 → 下发小程序 Bearer Token（存 `wx.setStorageSync`）。
- 打通 `templates` / `capabilities` / `quote` 三个只读接口的真机联调。
- 产出：能拉到模板与报价的小程序 Demo。

### Phase 2 — 核心创作闭环（≈2–2.5 周）
- 页面：工作台（模板浏览 + 创作表单**含参考图上传（图生图）** + 预览）、历史列表与详情。
- 组件：模板卡片、参考图上传（图生图）、报价展示、生成预览、历史项、积分展示。
- 接口：上传（参考图，经审核）、`generations` 创建/列表/详情/删除、输出下载（短期私有地址）。
- **图生图**：参考图经上传+审核后随请求传入（`referenceAssetId` → 供应商 `referenceImageUrl`），支持垫图/风格编辑；模板 `inputPolicy` 控制是否必填/禁用参考图。
- 轮询任务状态（queued → running → moderating → completed）。
- 产出：文本生图 + 图生图完整闭环（MVP 可上线）。

### Phase 3 — 创作额度包与个人虚拟支付（≈1–1.5 周）
- 新增**个人虚拟支付适配层** `virtualpay.ts`：后端 `/pay/order` 用 OfferID+AppKey 生成签名并下发 `payData`；前端 `wx.requestVirtualPayment` 拉起；`/pay/notify` 接收发货推送（幂等去重）后增加用户生图额度；`/pay/query` 兜底查单。
- 售卖标的为「创作额度包」道具（`quota_60/200/600`），**禁止**以"积分/虚拟货币"作为购买标的（个人虚拟支付红线）。内部仍用现有 credits 账本计量。
- 钱包余额（生图额度）、账单流水展示。
- 产出：可内购额度包的小程序。

### Phase 4 — 我的 / 设置 / 隐私合规（≈1 周）
- 「我的」页：钱包、订单、设置、退出。
- 隐私协议弹窗（微信强制要求）、相册授权引导、内容安全说明。
- 多端账号打通（开放平台 unionid，可选）。

### Phase 5 — 性能优化、审核与提审上线（≈1–1.5 周）
- 分包与体积优化（主包 < 2MB）、`setData` 优化、图片懒加载、启动耗时压到 1.5s 内（中端安卓）。
- 真机全量测试（iOS/Android、多分辨率、弱网）。
- 提审材料、规避常见驳回点（隐私、类目、权限用途说明）。
- 产出：审核通过、正式发布。

## 4. 小程序架构设计

### 4.1 总体架构（见图：小程序总体架构图）

小程序作为**新客户端**接入现有后端。核心设计原则：**后端业务逻辑零重复，仅加「适配层」**。

- **客户端**：微信小程序（WXML/WXSS/JS），分包管理体积。
- **网关**：微信要求所有请求 HTTPS + 域名白名单（备案域名）。
- **后端新增层**：`/api/miniprogram/*` 标准 REST（替代 TanStack serverFn 的 RPC，供 `wx.request` 调用）。
- **后端复用层**：认证桥接、微信支付 provider、审核、报价、钱包、模板、任务编排——全部复用现有模块。
- **外部依赖**：D1（SQLite）、R2（对象存储）、KV（缓存）、Kie/fal.ai/Workers AI（生图）、微信支付 API、微信开放接口（code2session）。

### 4.2 客户端架构（目录结构）

```
miniprogram/
├── app.js                 # 全局生命周期、globalData（token、用户信息、能力配置）
├── app.json               # 页面路由、window、tabBar、分包声明、权限声明
├── app.wxss               # 全局样式（深色主题、琥珀强调色、字号层级）
├── project.config.json    # 项目配置（AppID、编译设置）
├── sitemap.json           # 微信搜索索引
├── pages/                 # 主包（< 2MB，核心创作闭环）
│   ├── workbench/         # 工作台：模板浏览 + 创作表单 + 预览（首页 tab）
│   ├── history/           # 生成历史列表 + 详情 + 下载
│   ├── auth/              # 微信登录授权页
```

### 4.3 后端对接架构（新增 + 复用）

在现有 Cloudflare Worker 新增一组标准 REST 接口（与 `src/api/image-creator.ts` 的 serverFn 一一对应，复用其校验/业务逻辑）：

| 小程序接口 | 复用现有逻辑 | 说明 |
|-----------|------------|------|
| `POST /api/miniprogram/auth/login` | 新增：微信 code2session + Better Auth 用户关联 | 下发 Bearer Token |
| `GET  /api/miniprogram/templates` | `getImageCreatorTemplates` | 公开模板 DTO |
| `GET  /api/miniprogram/capabilities` | `getImageCreatorCapabilities` | 模式/比例/张数/上传限制 |
| `GET  /api/miniprogram/policy` | `getImageCreatorPolicy` | 隐私/条款版本与链接 |
| `POST /api/miniprogram/quote` | `quoteImageCreatorDraft` | 服务端权威报价（防抖 300ms） |
| `POST /api/miniprogram/upload` | `uploadImageCreatorReference` | 参考图（图生图，经审核后随生成传入） |
| `POST /api/miniprogram/generations` | `startImageCreatorGeneration` | 创建任务（幂等键） |
| `GET  /api/miniprogram/generations` | 新增列表查询 | 私有历史 |
| `GET  /api/miniprogram/generations/:id` | 任务详情 | 状态/输出 |
| `DELETE /api/miniprogram/generations/:id` | 软删除 | 历史删除 |
| `GET  /api/miniprogram/outputs/:id/download` | 短期私有下载地址 | 下载/保存 |
| `GET  /api/miniprogram/wallet` | 钱包查询 | 余额/流水 |
| `POST /api/miniprogram/pay/order` | 新增：个人虚拟支付适配层 | 额度包直购下单（OfferID/AppKey 签名） |
| `POST /api/miniprogram/pay/notify` | 新增：虚拟支付发货推送 | 验签 + 幂等发货（wx_order_id 去重） |
| `POST /api/miniprogram/pay/query` | 新增：query_order 转发 | 兜底查单补发货 |

**认证改造**：现有 Better Auth 用 cookie session（Web 端）。小程序 `wx.request` 不自动带 cookie，需改为 **Bearer Token 模式**：登录后把 token 存 `wx.setStorageSync('access_token')`，`utils/request.js` 统一注入 `Authorization` 头；401 触发重新 `wx.login` 换 token。所有权过滤（`userId`）逻辑完全复用。

**支付改造**：个人虚拟支付不走商户号 V3，改为新增 `virtualpay.ts` 适配层——后端 `/pay/order` 用 OfferID+AppKey 生成 `signData`/`paySig`/`signature`，前端 `wx.requestVirtualPayment` 拉起；`/pay/notify` 接收发货推送（幂等，以 `wx_order_id` 去重）后给对应用户增加生图额度；`/pay/query` 兜底查单。道具（额度包）售卖，复用现有 credits 账本做内部计量。

### 4.4 三个关键流程

**① 微信登录（首次/换 token）**
```
wx.login() → code
  → POST /auth/login { code }
  → Worker: code2session(openid) → 关联/创建 Better Auth 用户
  → 返回 access_token（存本地）
  → 后续请求带 Authorization: Bearer <token>
```

**② 创作生成闭环**
```
选模板/自由创作 → 填描述/参数 → 防抖请求 /quote（显示积分报价）
  → 勾选隐私同意 + 余额充足 → 点击生成
  → POST /generations（带 quoteId + 幂等键）
  → 轮询 GET /generations/:id（queued→running→moderating→completed）
  → 展示输出图 → /outputs/:id/download 保存
```

**③ 创作额度包直购（个人虚拟支付）**
```
进入 /pay 分包 → 选额度包道具 → POST /pay/order（后端用 OfferID/AppKey 签名）
  → 返回 payData → wx.requestVirtualPayment 拉起支付
  → 平台发货推送 /pay/notify（或 query_order 兜底）→ 后端给对应用户 +N 生图额度
  → 钱包余额更新（内部 credits 记账）
```

### 4.5 分包与体积策略
- **主包（< 2MB）**：工作台、历史、登录、结果页 + 公共组件/工具。模板数据与图片全部远程加载，不打包。
- **分包**：`profile`（我的）、`pay`（积分购买）独立分包，按需加载。
- 图片走 CDN/WebP + 懒加载；`setData` 只传视图所需字段，批量合并更新；启动非关键初始化后置。

### 4.6 数据流与状态管理
- 积分真值只在服务端（钱包表），小程序不缓存余额做扣减判断。
- 本地只保存：短期草稿、公开模板字段、quoteId、任务 id、access_token。
- 全局状态用 `app.globalData` + 极简 store，避免引入重型框架（小程序双线程架构，重状态库收益低）。

## 5. 关键技术决策与风险

| 风险/决策点 | 影响 | 应对 |
|------------|------|------|
| **Cloudflare 中国大陆访问** | 若目标用户含国内用户，Cloudflare 无大陆节点，延迟/可达性风险 | 明确目标：出海用户→Cloudflare 够用；国内用户→需额外大陆加速/反向代理或独立部署。这是产品决策，需先定。 |
| **域名备案** | 小程序强制要求 request/upload/download 域名 ICP 备案；`*.workers.dev` 不行 | Phase 0 必须完成 `api.jevailab.com` 备案（备案周期约 1–3 周，最早启动）。 |
| **个人虚拟支付合规** | 个人虚拟支付仅限「工具」类目 + 已备案；售卖标的须为"额度包"道具，禁售"积分/虚拟货币"；月限额 10 万 | 后端新增虚拟支付适配层（OfferID/AppKey 双签名）；对外文案统一为"创作额度"；定价对标现有套餐换算人民币。 |
| **图生图供应商切换** | 需把 image-creator 供应商从 Kie（纯文本）切到 GPT Image 2.5 Sunburst（图生图），并移除 `startImageCreatorGeneration` 的参考图硬拒绝；`referenceImageUrl` 字段已就位 | 后端改动小且可独立验证；小程序端参考图上传/审核流程已就绪，传入即生效。 |
| **审核 fail-closed** | 未配置审核则生成被阻断 | 复用现有审核适配器；生产环境务必先配置审核再开放生成。 |
| **AI 类目与提审** | 个人虚拟支付限「工具」类目；AI 生图若被判定"深度合成"营销类可能受限 | 类目选"工具-图片/音视频处理"（纯工具属性），提审时说明为图片编辑工具而非 AI 内容社区；隐私协议、权限用途说明齐全。 |
| **包体积 2MB** | 主包超限无法上传 | 分包 + 远程资源 + 轻量组件库，主包控制在 1.5MB 内留余量。 |
| **认证体系切换** | 现有 cookie session 不适用小程序 | Bearer Token 模式，复用所有权过滤，不改动 Better Auth 核心。 |

## 6. 与现有 Web 端的关系（多端统一）

- **一套后端、一份数据**：小程序与 Web 共享 D1/R2/KV、钱包、订单、模板、任务。用户在小程序买的积分、生成的历史，在 Web 端同样可见（通过 unionid/账号关联）。
- **品牌一致**：沿用 Jevailab 深色极简 + 琥珀强调的视觉语言，小程序做深色主题适配。
- **能力对齐**：小程序首版覆盖 Web 工作台的核心生图闭环；模板后台、图生图、广场等随后端能力演进逐步补齐。
